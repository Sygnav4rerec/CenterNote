Build Sheet: Distraction Free Notes App

Centered Notes — Build Sheet (Hand-off for Replit)
0) TL;DR

A distraction-free notes app with a centered input, history scrolling upward, inline editing, bottom glyph palette (3 rows), dark UI, and local persistence. No left rail; notes/history live on the main canvas with minimal chrome.

1) Product Intent

Why: Remove friction and visual noise during note-taking and meta-cognitive journaling. Keep the cursor in the visual center so typing feels grounded.

Philosophy: Minimal chrome, fast keyboard flow, zero setup.

Audience: Writers, students, thinkers, anyone who wants a calm writing surface.

2) UX Principles

Centered input: Editor stays vertically centered above the bottom glyph toolbar.

Enter to commit: Each Enter saves a line to history and scrolls it up.

Inline edits: Double-click any past line to edit (Enter to save, Esc to cancel).

Lightweight menus: Single top-right menu; no left rail.

Glyphs: Bottom toolbar with common math/chem/logic/emoji symbols (3 rows).

3) Core Features (MVP)

Centered, monospace editor (contenteditable).

History feed above the editor; smooth scroll on commit.

Inline edit of submitted lines (double-click to edit; blur or Enter saves).

Glyph toolbar (3 rows) inserts at caret (editor or inline edit target).

Local persistence via localStorage.

Export .txt of the current session/history.

Font size +/- control.

Help / shortcuts dialog.

Dark theme (built-in).

Keyboard

Enter — commit line

Shift+Enter — newline in editor or while inline-editing

Esc — clear editor / close menu / cancel inline edit

4) Non-Functional

No dependencies. Single index.html.

Responsive; mobile-friendly.

Works offline (no backend required).

Privacy: All data stays in-browser (localStorage).

6) Known Issues to Fix Before Deploy (quick patches)

The current canvas file shows some merge artifacts. Apply these two quick fixes:

A) Fix renderHistory() (remove stray “note” references)

Replace your current renderHistory() with this exact version:

function renderHistory() {
  historyEl.innerHTML = '';
  const frag = document.createDocumentFragment();
  state.lines.forEach((text, idx) => {
    const div = document.createElement('div');
    div.className = 'line';
    div.dataset.index = idx;
    div.textContent = text;
    frag.appendChild(div);
  });
  historyEl.appendChild(frag);
  historyEl.scrollTop = historyEl.scrollHeight;
}

B) Fix inline edit to write back to state.lines

In the enterEdit(el) function, replace the finish(commit) section with:

function finish(commit) {
  el.removeEventListener('keydown', onKey);
  el.removeEventListener('blur', onBlur);
  el.contentEditable = 'false';
  el.classList.remove('editing');
  if (commit) {
    const idx = Number(el.dataset.index);
    state.lines[idx] = el.textContent;
    save();
  } else {
    renderHistory(); // discard uncommitted HTML
  }
}

9) Optional Cloud Sync (Supabase)

Only if you want multi-device sync now. Minimal schema:

create table notes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  title text not null default 'Untitled',
  lines text[] not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index on notes (user_id, updated_at desc);

-- RLS (row-level security)
alter table notes enable row level security;
create policy "own notes" on notes
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);


Client pattern:

On load: select notes order by updated_at desc.

On commit/inline edit: update lines and updated_at.

Optimistic UI; debounce network writes.
